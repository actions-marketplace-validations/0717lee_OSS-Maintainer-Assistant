# maintainer-agent - Design Write-up

## The problem

Open-source maintainers are burning out, and 2025-2026 added a new accelerant:
**AI slop**. Contributors now open large, confident, low-effort pull requests and
issues generated by LLMs. Reviewing them is *more* taxing than human work because
the text looks plausible while the substance is thin. The signals are everywhere:
Godot maintainers calling AI PRs "draining and demoralizing", OCaml rejecting a
13,000-line generated PR, LLVM drafting an AI-tool policy, and GitHub shipping
per-repo PR rate limits.

## Why existing tooling doesn't solve it

Almost every response so far is **defensive**: throttles, caps, filters, and
"close with a template" bots. They reduce volume but don't help a maintainer with
the actual work - deciding what matters, why, and what to say back. They're also
opaque: a filter that silently drops a contribution erodes newcomer trust.

## Approach: a small team of explainable agents

`maintainer-agent` flips this into a **proactive, explainable, human-gated**
assistant. A LangGraph pipeline runs a few focused agents per issue/PR:

- **Triage** - labels, priority, duplicate detection (vector similarity), and
  "needs more info" / good-first-issue spotting.
- **Quality / AI-slop** - the headline. It reads the repo's `CONTRIBUTING.md` as
  the contribution bar ("job description") and accumulates *weighted, named
  signals* into a score.
- **Reproducer** - runs a bug's snippet in a locked-down Docker sandbox and
  reports whether it actually reproduces.
- **Responder** - drafts a specific, respectful reply from the findings.
- **Digest** - a 30-second summary of the whole tracker.

The design goal throughout: a maintainer should be able to see **exactly why**
each conclusion was reached and stay in control of anything that leaves the repo.

## Key engineering decisions

- **Explainability as a first-class type.** Every `Decision` carries a verdict,
  confidence, and a list of weighted `Evidence`. The UI and CLI render these, so
  nothing is a black box.
- **Human-in-the-loop by construction.** Read-only by default; actions are only
  *proposed*. Posting requires `--apply` **and** per-action approval **and**
  `--allow-write` with a token. The read path and the (isolated) write path are
  different modules, so the system is provably read-only unless explicitly told
  otherwise.
- **Offline-first determinism.** With no keys, a rule-based `MockLLM` and bundled
  fixtures drive the whole pipeline. This makes demos, CI, and the eval harness
  reproducible - and it means the heuristics carry real weight instead of hiding
  behind a model.
- **Optional heavy deps, graceful fallback.** LangGraph (graph engine), litellm
  (LLM), and FAISS/Chroma (vector store) are all import-guarded. Missing any of
  them degrades cleanly (linear orchestrator, MockLLM, TF-IDF index) rather than
  crashing.
- **Safety-first sandbox.** Snippets run via `--network none`, all caps dropped,
  read-only FS, memory/CPU/PID limits, and a timeout - piped over stdin so there
  are no host mounts.
- **Reliability is measured, not asserted.** A labeled dataset + a metrics harness
  turn "seems smart" into precision/recall/F1 and double as a CI regression gate.

## How AI-slop scoring works

Rather than one opaque number, signals are additive and legible. On the demo's
PR #103 ("Improve codebase and enhance overall functionality"):

```
quality -> likely-ai-slop (slop 1.0)
  - [heuristic] generic AI-style phrasing (6): "improves the overall", ... (+0.40)
  - [heuristic] no linked issue (CONTRIBUTING asks PRs to reference one)  (+0.20)
  - [heuristic] sweeping change: 12 files, 3234 lines                     (+0.25)
  - [heuristic] touches code (9 file(s)) but adds no tests                (+0.20)
```

Positive signals (linked issue, included tests, small focused diff) subtract, so
a clean fix like PR #104 scores `looks-good (0.0)`. When an LLM key is present it
refines the score and rationale; offline, the heuristics stand on their own.

## Reliability, measured

On the curated fixture set (`maintainer-agent eval`):

| Task | Metric | Score |
|------|--------|-------|
| AI-slop detection | precision / recall / F1 | 1.00 / 1.00 / 1.00 |
| Duplicate detection | accuracy | 1.00 |
| Priority | accuracy | 1.00 |
| Label coverage | accuracy | 1.00 |

Scores are high by design on a tiny curated set; the point is the *methodology* -
point `--dataset` at real labels for a true measurement.

## What I'd do next

- A contributor/skill **Matcher** (good-first-issues to newcomers).
- CI-failure summarization and multi-language reproduction.
- Package as a GitHub App with a review UI over the audit log.
- Larger, real-world labeled eval sets per ecosystem.

## Reproducing the demo assets

The dashboard screenshot in `docs/assets/` was captured from
`maintainer-agent serve`. To record a GIF, run the server, open the dashboard,
expand a flagged PR to show its evidence + reply draft, and screen-record the
interaction (any recorder). The pipeline itself is deterministic offline, so the
demo is repeatable.

## 中文摘要

开源维护者正被 2025-2026 兴起的 **AI 生成低质内容（AI slop）** 淹没。现有工具多是
"过滤 / 限流" 的被动防御，既帮不上真正的评审工作，也不透明。本项目反其道而行：做一个
**主动、可解释、人类可控** 的多 Agent 维护助手（分诊 / AI-slop 质量评估 / 沙箱复现 /
回复草稿 / 摘要），用 LangGraph 编排，默认只读 + dry-run，所有外发动作需人工逐条批准，
并以带权重的证据解释每一个判断。可靠性用带标注数据集 + precision/recall 量化，离线可
复现。向量检索默认 TF-IDF，可切换 FAISS / Chroma；LLM 通过 litellm 抽象，均为可选依赖，
缺失时优雅降级。
